Clickjacking

ID
WSTG-CLNT-09

Resumen

El clickjacking, un subconjunto del UI redressing, es una técnica maliciosa mediante la cual se engaña a un usuario web para que interactúe (en la mayoría de los casos haciendo clic) con algo distinto de aquello con lo que cree estar interactuando. Este tipo de ataque, ya sea solo o en conjunto con otros ataques, podría enviar comandos no autorizados o revelar información confidencial mientras la víctima interactúa con páginas web aparentemente inofensivas. El término clickjacking fue acuñado por Jeremiah Grossman y Robert Hansen en 2008.

Un ataque de clickjacking utiliza características aparentemente inofensivas de HTML y JavaScript para forzar a la víctima a realizar acciones no deseadas, como hacer clic en un botón invisible que ejecuta una operación no prevista. Es un problema de seguridad del lado del cliente que afecta a una variedad de navegadores y plataformas.

Para llevar a cabo este ataque, un atacante crea una página web aparentemente inofensiva que carga la aplicación objetivo mediante un marco en línea (inline frame) oculto con código CSS. Una vez hecho esto, el atacante puede inducir a la víctima a interactuar con la página web por otros medios (por ejemplo, mediante ingeniería social). Como en otros ataques, un requisito previo común es que la víctima esté autenticada en la aplicación objetivo del atacante.


Figura 4.11.9-1: Ilustración de un inline frame para clickjacking

La víctima navega por la página web del atacante con la intención de interactuar con la interfaz de usuario visible, pero sin darse cuenta realiza acciones sobre la página web oculta. Utilizando la página oculta, un atacante puede engañar a los usuarios para que realicen acciones que nunca pretendieron realizar mediante el posicionamiento de los elementos ocultos en la página web.


Figura 4.11.9-2: Ilustración de un inline frame enmascarado

El poder de este método es que las acciones realizadas por la víctima se originan en la página web objetivo, oculta pero auténtica. En consecuencia, algunas de las protecciones anti-CSRF implementadas por los desarrolladores para proteger la página web de ataques CSRF podrían eludirse.

Objetivos de la prueba

  • Evaluar la vulnerabilidad de la aplicación a ataques de clickjacking.

Cómo probar

Como se mencionó anteriormente, este tipo de ataque suele diseñarse para permitir a un atacante inducir acciones de los usuarios en el sitio objetivo, incluso si se utilizan tokens anti-CSRF.

Cargar la página web objetivo en un intérprete de HTML mediante la etiqueta iframe

Los sitios que no están protegidos contra el frame busting son vulnerables al ataque de clickjacking. Si la página web https://www.target.site se carga con éxito en un frame, entonces el sitio es vulnerable a Clickjacking. A continuación se muestra un ejemplo de código HTML para crear esta página web de prueba:

    <html>
        <head>
            <title>Clickjack test web page</title>
        </head>
        <body>
            <iframe src="https://www.target.site" width="400" height="400"></iframe>
        </body>
    </html>

Probar la aplicación con JavaScript deshabilitado

Dado que este tipo de protecciones del lado del cliente depende de código de frame busting en JavaScript, si la víctima tiene JavaScript deshabilitado o si un atacante puede deshabilitar el código JavaScript, la página web no tendrá ningún mecanismo de protección contra el clickjacking.

Hay algunas técnicas de desactivación que pueden utilizarse con los frames. Se pueden encontrar técnicas más detalladas en la Clickjacking Defense Cheat Sheet.

Atributo sandbox

Con HTML5 está disponible un nuevo atributo llamado "sandbox". Este habilita un conjunto de restricciones sobre el contenido cargado en el iframe.

Ejemplo:

<iframe src="https://example.org" sandbox></iframe>

Probar la aplicación en modo de compatibilidad y accesibilidad

Las versiones móviles de la página web suelen ser más pequeñas y rápidas que las de escritorio, y tienen que ser menos complejas que la aplicación principal. Las variantes móviles suelen tener menos protección. Sin embargo, un atacante puede falsificar el origen real proporcionado por un navegador web, y una víctima que no use un dispositivo móvil podría visitar una aplicación hecha para usuarios móviles. Este escenario podría permitir al atacante explotar una versión móvil de la página web. Las aplicaciones que se ejecutan en modo de accesibilidad también deben probarse contra el clickjacking, porque el enmarcado del sitio podría verse afectado.

Protección del lado del servidor: uso de la directiva frame-ancestors de Content Security Policy

La cabecera de respuesta HTTP Content-Security-Policy (CSP) permite a los administradores de páginas web controlar los recursos que el user agent puede cargar para una página web determinada. La directiva frame-ancestors de la CSP HTTP especifica los padres aceptables que pueden incrustar una página web mediante las etiquetas <frame>, <iframe>, <object>, <embed> o <applet>.

Cabecera de respuesta Content Security Policy

  • Con un navegador, abra las herramientas de desarrollo y acceda a la página web objetivo. Navegue a la pestaña Network.
  • Busque la petición que carga la página web. Debe tener el mismo dominio que la página web; normalmente es el primer elemento de la pestaña Network.
  • Al hacer clic en el archivo, aparecerá más información. Busque un código de respuesta 200 OK.
  • Desplácese hasta la sección Response Header. La sección Content-Security-Policy indica el nivel de protección adoptado.

Alternativamente, vea el código fuente de la página web para encontrar Content-Security-Policy en una etiqueta meta. La WSTG contiene información detallada sobre la Content Security Policy.

Proxies

Se sabe que los proxies web añaden y eliminan cabeceras. En el caso de que un proxy web elimine la cabecera X-FRAME-OPTIONS, el sitio pierde su protección contra el enmarcado.

Versión móvil de la aplicación

En este caso, como la cabecera HTTP X-FRAME-OPTIONS debe implementarse en cada página de la aplicación, es posible que los desarrolladores no hayan protegido todas y cada una de las páginas de la versión móvil.
