Reverse Tabnabbing

ID
WSTG-CLNT-14

Resumen

Reverse Tabnabbing es un ataque que puede utilizarse para redirigir a los usuarios a páginas de phishing. Normalmente es posible porque el atributo target de la etiqueta <a> está establecido en _blank, lo que hace que el enlace se abra en una nueva pestaña. Cuando el atributo rel='noopener noreferrer' no se usa en la misma etiqueta <a>, la página recién abierta puede influir en la página original y redirigirla a un dominio controlado por el atacante.

Dado que el usuario estaba en el dominio original cuando se abrió la nueva pestaña, es menos probable que note que la página ha cambiado, especialmente si la página de phishing es idéntica al dominio original. Por lo tanto, cualquier credencial introducida en el dominio controlado por el atacante terminará en poder de este.

Los enlaces abiertos mediante la función de JavaScript window.open también son vulnerables a este ataque.

NOTA: Este es un problema heredado que no afecta a los navegadores modernos. Las versiones antiguas de navegadores populares (por ejemplo, las versiones anteriores a Google Chrome 88), así como Internet Explorer, son vulnerables a este ataque.

Ejemplo

Imagine una aplicación web en la que se permite a los usuarios insertar una URL en su perfil. Si la aplicación es vulnerable a reverse tabnabbing, un usuario malicioso podrá proporcionar un enlace a una página que tenga el siguiente código:

<html>
 <body>
  <script>
    window.opener.location = "https://example.org";
  </script>
<b>Error loading...</b>
 </body>
</html>

Al hacer clic en el enlace se abrirá una nueva pestaña mientras la pestaña original se redirige a "example.org". Suponiendo que "example.org" se parezca a la aplicación web vulnerable, es menos probable que el usuario note el cambio y es más probable que introduzca información sensible en la página.

Cómo probar

  • Revisar el código fuente HTML de la aplicación para ver si los enlaces con target="_blank" usan las palabras clave noopener y noreferrer en el atributo rel. Si no es así, es probable que la aplicación sea vulnerable a reverse tabnabbing. Un enlace de este tipo se vuelve explotable si apunta a un sitio de terceros que ha sido comprometido por el atacante, o si está controlado por el usuario.
  • Buscar áreas donde un atacante pueda insertar enlaces, es decir, controlar el argumento href de una etiqueta <a>. Intentar insertar un enlace a una página que tenga el código fuente dado en el ejemplo anterior y comprobar si el dominio original se redirige. Esta prueba puede hacerse en IE si otros navegadores no funcionan.

Corrección

Se recomienda asegurarse de que el atributo HTML rel esté establecido con las palabras clave noreferrer y noopener en todos los enlaces.
