Ejecución de JavaScript

ID
WSTG-CLNT-02

Resumen

Una vulnerabilidad de inyección de JavaScript es un subtipo de cross site scripting (XSS) que implica la capacidad de inyectar código JavaScript arbitrario que la aplicación ejecuta dentro del navegador de la víctima. Esta vulnerabilidad puede tener muchas consecuencias, como la divulgación de las cookies de sesión de un usuario, que podrían usarse para suplantar a la víctima, o, de forma más general, puede permitir al atacante modificar el contenido de la página que ven las víctimas o el comportamiento de la aplicación.

Las vulnerabilidades de inyección de JavaScript pueden ocurrir cuando la aplicación carece de una validación adecuada de la entrada y la salida proporcionadas por el usuario. Como JavaScript se utiliza para rellenar dinámicamente las páginas web, esta inyección ocurre durante esa fase de procesamiento del contenido y, en consecuencia, afecta a la víctima.

Al probar esta vulnerabilidad, hay que considerar que algunos caracteres son tratados de manera diferente por distintos navegadores. Como referencia, consulte DOM-based XSS.

Este es un ejemplo de un script que no realiza ninguna validación de la variable rr. La variable contiene entrada proporcionada por el usuario a través de la cadena de consulta (query string) y, además, no aplica ninguna forma de codificación:

var rr = location.search.substring(1);
if(rr) {
    window.location=decodeURIComponent(rr);
}

Esto implica que un atacante podría inyectar código JavaScript simplemente enviando la siguiente cadena de consulta: www.victim.com/?javascript:alert(1).

Objetivos de la prueba

  • Identificar sinks y posibles puntos de inyección de JavaScript.

Cómo probar

Considere una página que contiene el siguiente script:

<script>
function loadObj(){
    var cc=eval('('+aMess+')');
    document.getElementById('mess').textContent=cc.message;
}

if(window.location.hash.indexOf('message')==-1) {
    var aMess='({"message":"Hello User!"})';
} else {
    var aMess=location.hash.substr(window.location.hash.indexOf('message=')+8)
}
</script>

El código anterior contiene una fuente (source), location.hash, controlada por el atacante, que puede inyectar directamente en el valor de message código JavaScript para tomar el control del navegador del usuario.
