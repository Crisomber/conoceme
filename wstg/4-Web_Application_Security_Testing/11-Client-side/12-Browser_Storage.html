Almacenamiento del navegador

ID
WSTG-CLNT-12

Resumen

Los navegadores proporcionan los siguientes mecanismos de almacenamiento del lado del cliente para que los desarrolladores almacenen y recuperen datos:

  • LocalStorage
  • SessionStorage
  • IndexedDB
  • Cookies

Estos mecanismos de almacenamiento pueden verse y editarse con las herramientas para desarrolladores del navegador, como Google Chrome DevTools o el Storage Inspector de Firefox.

Nota: Aunque la caché también es una forma de almacenamiento, se cubre en una sección aparte que trata sus propias peculiaridades y preocupaciones.

Objetivos de la prueba

  • Determinar si el sitio almacena datos sensibles en el almacenamiento del lado del cliente.
  • Se debe examinar el código que maneja los objetos de almacenamiento en busca de posibilidades de ataques de inyección, como el uso de entrada sin validar o bibliotecas vulnerables.

Cómo probar

LocalStorage

window.localStorage es una propiedad global que implementa la Web Storage API y proporciona almacenamiento clave-valor persistente en el navegador.

Tanto las claves como los valores solo pueden ser cadenas, por lo que cualquier valor que no sea una cadena debe convertirse primero a cadena antes de almacenarse, normalmente mediante JSON.stringify.

Las entradas de localStorage persisten incluso cuando se cierra la ventana del navegador, con la excepción de las ventanas en modo Privado/Incógnito.

La capacidad máxima de almacenamiento de localStorage varía entre navegadores.

Listar todas las entradas clave-valor

for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i);
  const value = localStorage.getItem(key);
  console.log(`${key}: ${value}`);
}

SessionStorage

window.sessionStorage es una propiedad global que implementa la Web Storage API y proporciona almacenamiento clave-valor efímero en el navegador.

Tanto las claves como los valores solo pueden ser cadenas, por lo que cualquier valor que no sea una cadena debe convertirse primero a cadena antes de almacenarse, normalmente mediante JSON.stringify.

Las entradas de sessionStorage son efímeras porque se borran cuando se cierra la pestaña/ventana del navegador.

La capacidad máxima de almacenamiento de sessionStorage varía entre navegadores.

Listar todas las entradas clave-valor

for (let i = 0; i < sessionStorage.length; i++) {
  const key = sessionStorage.key(i);
  const value = sessionStorage.getItem(key);
  console.log(`${key}: ${value}`);
}

IndexedDB

IndexedDB es una base de datos transaccional orientada a objetos destinada a datos estructurados. Una base de datos IndexedDB puede tener múltiples almacenes de objetos (object stores) y cada almacén de objetos puede tener múltiples objetos.

A diferencia de localStorage y sessionStorage, IndexedDB puede almacenar más que simples cadenas. En IndexedDB se puede almacenar cualquier objeto compatible con el algoritmo de clonación estructurada.

Un ejemplo de un objeto JavaScript complejo que puede almacenarse en IndexedDB, pero no en localStorage/sessionStorage, son las CryptoKeys.

La recomendación del W3C sobre la Web Crypto API recomienda que las CryptoKeys que necesiten persistir en el navegador se almacenen en IndexedDB. Al probar una página web, hay que buscar cualquier CryptoKey en IndexedDB y comprobar si están configuradas como extractable: true cuando deberían haberse configurado como extractable: false (es decir, asegurar que el material de la clave privada subyacente nunca se exponga durante las operaciones criptográficas).

Imprimir todo el contenido de IndexedDB

const dumpIndexedDB = dbName => {
  const DB_VERSION = 1;
  const req = indexedDB.open(dbName, DB_VERSION);
  req.onsuccess = function() {
    const db = req.result;
    const objectStoreNames = db.objectStoreNames || [];

    console.log(`[*] Database: ${dbName}`);

    Array.from(objectStoreNames).forEach(storeName => {
      const txn = db.transaction(storeName, 'readonly');
      const objectStore = txn.objectStore(storeName);

      console.log(`\t[+] ObjectStore: ${storeName}`);

      // Print all entries in objectStore with name `storeName`
      objectStore.getAll().onsuccess = event => {
        const items = event.target.result || [];
        items.forEach(item => console.log(`\t\t[-] `, item));
      };
    });
  };
};

indexedDB.databases().then(dbs => dbs.forEach(db => dumpIndexedDB(db.name)));

Cookies

Las cookies son un mecanismo de almacenamiento clave-valor que se utiliza principalmente para la gestión de sesiones, pero los desarrolladores web aún pueden usarlas para almacenar datos de cadena arbitrarios.

Las cookies se tratan extensamente en el escenario de pruebas de atributos de cookies.

Listar todas las cookies

console.log(window.document.cookie);

Objeto global window

A veces los desarrolladores web inicializan y mantienen un estado global que solo está disponible durante el tiempo de ejecución de la página, asignando atributos personalizados al objeto global window. Por ejemplo:

window.MY_STATE = {
  counter: 0,
  flag: false,
};

Cualquier dato adjunto al objeto window se perderá cuando la página se actualice o se cierre.

Listar todas las entradas del objeto window

(() => {
  // create an iframe and append to body to load a clean window object
  const iframe = document.createElement('iframe');
  iframe.style.display = 'none';
  document.body.appendChild(iframe);

  // get the current list of properties on window
  const currentWindow = Object.getOwnPropertyNames(window);

  // filter the list against the properties that exist in the clean window
  const results = currentWindow.filter(
    prop => !iframe.contentWindow.hasOwnProperty(prop)
  );

  // remove iframe
  document.body.removeChild(iframe);

  // log key-value entries that are different
  results.forEach(key => console.log(`${key}: ${window[key]}`));
})();

Implicaciones de seguridad

Al revisar los mecanismos de almacenamiento del navegador, los evaluadores deben valorar si se expone innecesariamente información sensible en el lado del cliente. Las aplicaciones modernas, especialmente las SPA, almacenan con frecuencia tokens de autenticación o el estado de la aplicación en el almacenamiento del navegador, lo que puede introducir riesgos de seguridad.

Las preocupaciones comunes incluyen:

  • Tokens de autenticación (p. ej., JWTs) almacenados en localStorage o sessionStorage, a los que se puede acceder mediante JavaScript y que pueden quedar expuestos por XSS.
  • Tokens o identificadores de sesión que persisten después de cerrar sesión.
  • Datos de negocio sensibles almacenados en IndexedDB o localStorage sin un requisito claro.
  • Material criptográfico almacenado como extraíble cuando debería estar protegido.

El almacenamiento inadecuado del lado del cliente puede aumentar el impacto de ataques del lado del cliente, como el XSS basado en DOM.

Guía general de pruebas

Además de enumerar las entradas de almacenamiento, los evaluadores deben:

  • Inspeccionar el almacenamiento del navegador con las herramientas para desarrolladores (pestaña Application/Storage).
  • Identificar tokens de autenticación, identificadores de sesión o datos de negocio sensibles.
  • Intentar acceder a los valores almacenados mediante la consola de JavaScript.
  • Verificar si las entradas de almacenamiento se borran tras cerrar sesión o expirar la sesión.
  • Valorar si los datos almacenados podrían aprovecharse en una cadena de ataque del lado del cliente.

Cadena de ataque

Tras la identificación de cualquiera de los vectores de ataque anteriores, se puede formar una cadena de ataque con distintos tipos de ataques del lado del cliente, como los ataques de XSS basado en DOM.

Corrección

Las aplicaciones deben almacenar los datos sensibles en el lado del servidor, y no en el lado del cliente, de manera segura y siguiendo las mejores prácticas.
