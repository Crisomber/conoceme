Proceso de registro de usuarios

ID
WSTG-IDNT-02

Resumen

Algunos sitios web ofrecen un proceso de registro de usuarios que automatiza (o semiautomatiza) el aprovisionamiento del acceso al sistema para los usuarios. Los requisitos de identidad para el acceso varían desde la identificación positiva hasta ninguno en absoluto, según los requisitos de seguridad del sistema. Muchas aplicaciones públicas automatizan por completo el proceso de registro y aprovisionamiento porque el tamaño de la base de usuarios hace imposible gestionarlo manualmente. Sin embargo, muchas aplicaciones corporativas aprovisionan a los usuarios de forma manual, por lo que este caso de prueba puede no aplicar.

Objetivos de la prueba

  • Verificar que los requisitos de identidad para el registro de usuarios estén alineados con los requisitos de negocio y de seguridad.
  • Validar el proceso de registro.

Cómo probar

Verificar que los requisitos de identidad para el registro de usuarios estén alineados con los requisitos de negocio y de seguridad:

  1. ¿Puede cualquier persona registrarse para obtener acceso?
  2. ¿Los registros son revisados por una persona antes del aprovisionamiento, o se otorgan automáticamente si se cumplen los criterios?
  3. ¿Puede la misma persona o identidad registrarse varias veces?
  4. ¿Pueden los usuarios registrarse para distintos roles o permisos?
  5. ¿Qué prueba de identidad se requiere para que un registro sea exitoso?
  6. ¿Se verifican las identidades registradas?

Validar el proceso de registro:

  1. ¿Puede la información de identidad falsificarse o simularse fácilmente?
  2. ¿Puede manipularse el intercambio de información de identidad durante el registro?

Ejemplo

En el siguiente ejemplo de WordPress, el único requisito de identificación es una dirección de correo electrónico a la que tenga acceso quien se registra.

En contraste, en el siguiente ejemplo de Google los requisitos de identificación incluyen nombre, fecha de nacimiento, país, número de teléfono móvil, dirección de correo electrónico y respuesta a un CAPTCHA. Aunque solo dos de ellos pueden verificarse (la dirección de correo electrónico y el número móvil), los requisitos de identificación son más estrictos que los de WordPress.


Figura 4.3.2-2: Página de registro de Google

Algunas aplicaciones también pueden otorgar automáticamente roles privilegiados a los usuarios cuando registran una cuenta con una dirección de correo electrónico de un dominio de confianza. Si la propiedad de la dirección de correo no se valida como parte del proceso de registro, esto podría permitir a un atacante obtener acceso a una cuenta privilegiada registrando un nuevo usuario en ese dominio.

Alternativamente, si solo realizan una coincidencia parcial del dominio, podría ser posible registrar una cuenta privilegiada utilizando otros dominios similares. Por ejemplo, si la aplicación comprueba direcciones de correo que terminan en example.org, podría ser posible usar el dominio notexample.org; o si comprueba que la dirección contenga @example.org, podría ser posible usar @example.org.attacker.com.

Corrección

Implementar requisitos de identificación y verificación que correspondan a los requisitos de seguridad de la información que protegen las credenciales.

Herramientas

Un proxy HTTP puede ser una herramienta útil para probar este control.
