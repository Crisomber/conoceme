Session Puzzling

ID
WSTG-SESS-08

Resumen

La sobrecarga de variables de sesión (Session Variable Overloading, también conocida como Session Puzzling) es una vulnerabilidad a nivel de aplicación que puede permitir a un atacante realizar diversas acciones maliciosas, entre ellas:

  • Eludir mecanismos eficaces de imposición de autenticación y suplantar a usuarios legítimos.
  • Elevar los privilegios de una cuenta de usuario maliciosa, en un entorno que de otro modo se consideraría infalible.
  • Saltarse fases de calificación en procesos de varias fases, incluso si el proceso incluye todas las restricciones a nivel de código comúnmente recomendadas.
  • Manipular valores del lado del servidor mediante métodos indirectos que no se pueden predecir ni detectar.
  • Ejecutar ataques tradicionales en ubicaciones que antes eran inalcanzables, o incluso consideradas seguras.

Esta vulnerabilidad ocurre cuando una aplicación utiliza la misma variable de sesión para más de un propósito. Un atacante puede acceder potencialmente a las páginas en un orden no previsto por los desarrolladores, de modo que la variable de sesión se establece en un contexto y luego se utiliza en otro.

Por ejemplo, un atacante podría usar la sobrecarga de variables de sesión para eludir los mecanismos de imposición de autenticación de aplicaciones que imponen la autenticación validando la existencia de variables de sesión que contienen valores relacionados con la identidad, que normalmente se almacenan en la sesión tras un proceso de autenticación exitoso. Esto significa que un atacante primero accede a una ubicación de la aplicación que establece el contexto de la sesión y luego accede a ubicaciones privilegiadas que examinan ese contexto.

Por ejemplo, un vector de ataque de elusión de autenticación podría ejecutarse accediendo a un punto de entrada accesible públicamente (p. ej., una página de recuperación de contraseña) que rellena la sesión con una variable de sesión idéntica, basada en valores fijos o en datos de entrada originados por el usuario.

Objetivos de la prueba

  • Identificar todas las variables de sesión.
  • Romper el flujo lógico de generación de la sesión.

Cómo probar

Pruebas de caja negra

Esta vulnerabilidad puede detectarse y explotarse enumerando todas las variables de sesión utilizadas por la aplicación y en qué contexto son válidas. En particular, esto es posible accediendo a una secuencia de puntos de entrada y luego examinando los puntos de salida. En el caso de las pruebas de caja negra este procedimiento es difícil y requiere algo de suerte, ya que cada secuencia diferente podría conducir a un resultado distinto.

Ejemplos

Un ejemplo muy sencillo podría ser la funcionalidad de restablecimiento de contraseña que, en el punto de entrada, podría solicitar al usuario que proporcione alguna información identificativa, como el nombre de usuario o la dirección de correo electrónico. Esta página podría entonces rellenar la sesión con estos valores identificativos, que se reciben directamente del lado del cliente o se obtienen de consultas o cálculos basados en la entrada recibida. En este punto puede haber algunas páginas en la aplicación que muestren datos privados basados en este objeto de sesión. De esta manera el atacante podría eludir el proceso de autenticación.

Pruebas de caja gris

La forma más eficaz de detectar estas vulnerabilidades es mediante una revisión del código fuente.

Corrección

Las variables de sesión solo deben usarse para un único propósito coherente.
