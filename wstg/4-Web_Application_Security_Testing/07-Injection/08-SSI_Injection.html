Inyección SSI

ID
WSTG-INJT-08

Resumen

Los servidores web suelen dar a los desarrolladores la posibilidad de añadir pequeños fragmentos de código dinámico dentro de páginas HTML estáticas, sin tener que recurrir a lenguajes completos del lado del servidor o del cliente. Esta funcionalidad la proporcionan los Server-Side Includes (SSI).

Los Server-Side Includes son directivas que el servidor web analiza antes de entregar la página al usuario. Representan una alternativa a escribir programas CGI o incrustar código mediante lenguajes de scripting del lado del servidor, cuando solo se necesita realizar tareas muy simples. Las implementaciones comunes de SSI proporcionan directivas (comandos) para incluir archivos externos, para establecer e imprimir variables de entorno CGI del servidor web, o para ejecutar scripts CGI externos o comandos del sistema.

SSI puede conducir a una ejecución remota de comandos (RCE); sin embargo, la mayoría de los servidores web tienen la directiva exec deshabilitada por defecto.

Esta es una vulnerabilidad muy similar a una vulnerabilidad clásica de inyección en lenguajes de scripting. Un factor atenuante es que el servidor web debe estar configurado para permitir SSI. Por otro lado, las vulnerabilidades de inyección SSI suelen ser más sencillas de explotar, ya que las directivas SSI son fáciles de entender y, al mismo tiempo, bastante potentes; por ejemplo, pueden mostrar el contenido de archivos y ejecutar comandos del sistema.

Objetivos de la prueba

  • Identificar los puntos de inyección SSI.
  • Evaluar la severidad de la inyección.

Cómo probar

Para probar si SSI es explotable, se inyectan directivas SSI como entrada del usuario. Si SSI está habilitado y la validación de la entrada del usuario no se ha implementado correctamente, el servidor ejecutará la directiva. Esto es muy similar a una vulnerabilidad clásica de inyección en lenguajes de scripting, en el sentido de que ocurre cuando la entrada del usuario no se valida ni se sanea adecuadamente.

Primero hay que determinar si el servidor web admite directivas SSI. A menudo la respuesta es afirmativa, ya que el soporte de SSI es bastante común. Para determinar si se admiten directivas SSI, se descubre el tipo de servidor web que ejecuta el objetivo mediante técnicas de recopilación de información (véase Fingerprint Web Server). Si se tiene acceso al código, se determina si se utilizan directivas SSI buscando palabras clave específicas en los archivos de configuración del servidor web.

Otra forma de verificar que las directivas SSI están habilitadas es comprobar si existen páginas con la extensión .shtml, que está asociada a las directivas SSI. El uso de la extensión .shtml no es obligatorio, por lo que no haber encontrado archivos .shtml no significa necesariamente que el objetivo no sea vulnerable a ataques de inyección SSI.

El siguiente paso es determinar todos los posibles vectores de entrada del usuario y probar si la inyección SSI es explotable.

Primero hay que encontrar todas las páginas donde se permite la entrada del usuario. Los posibles vectores de entrada también pueden incluir cabeceras y cookies. Se debe determinar cómo se almacena y se utiliza la entrada, es decir, si se devuelve como mensaje de error o elemento de la página y si fue modificada de alguna manera. El acceso al código fuente puede ayudar a determinar con más facilidad dónde están los vectores de entrada y cómo se maneja la entrada.

Una vez que se tiene una lista de posibles puntos de inyección, se puede determinar si la entrada se valida correctamente. Hay que asegurarse de que es posible inyectar los caracteres utilizados en las directivas SSI, como <!#=/."-> y [a-zA-Z0-9].

El siguiente ejemplo devuelve el valor de la variable. La sección de referencias contiene enlaces útiles con documentación específica de cada servidor para ayudar a evaluar mejor un sistema en particular.

<!--#echo var="VAR" -->

Al usar la directiva include, si el archivo suministrado es un script CGI, esta directiva incluirá la salida del script CGI. Esta directiva también puede utilizarse para incluir el contenido de un archivo o para listar los archivos de un directorio:

<!--#include virtual="FILENAME" -->

Para devolver la salida de un comando del sistema:

<!--#exec cmd="OS_COMMAND" -->

Si la aplicación es vulnerable, la directiva se inyecta y el servidor la interpretará la próxima vez que se sirva la página.

Las directivas SSI también pueden inyectarse en las cabeceras HTTP, si la aplicación web utiliza esos datos para construir una página generada dinámicamente:

GET / HTTP/1.1
Host: www.example.com
Referer: <!--#exec cmd="/bin/ps ax"-->
User-Agent: <!--#include virtual="/proc/version"-->
