Inyección ORM

Resumen

La inyección en Object Relational Mapping (ORM) es un ataque que usa inyección SQL contra un modelo de objetos de acceso a datos generado por un ORM. Desde el punto de vista de un evaluador, este ataque es prácticamente idéntico a un ataque de inyección SQL. Sin embargo, la vulnerabilidad de inyección existe en el código generado por la capa ORM.

Entre los beneficios de usar una herramienta ORM se incluyen la generación rápida de una capa de objetos para comunicarse con una base de datos relacional, la estandarización de las plantillas de código para esos objetos y que, por lo general, proporcionan un conjunto de funciones seguras para protegerse contra ataques de inyección SQL. Los objetos generados por un ORM pueden usar SQL o, en algunos casos, una variante de SQL, para realizar operaciones CRUD (Create, Read, Update, Delete) sobre una base de datos. Sin embargo, es posible que una aplicación web que use objetos generados por un ORM sea vulnerable a ataques de inyección SQL si los métodos pueden aceptar parámetros de entrada sin sanitizar.

Cómo probar

Las capas ORM pueden ser propensas a vulnerabilidades, ya que amplían la superficie de ataque. En lugar de atacar directamente la aplicación con consultas SQL, el enfoque estaría en abusar de la capa ORM para enviar consultas SQL maliciosas.

Identificar la capa ORM

Para probar de forma eficiente y entender qué sucede entre las peticiones y las consultas del backend, y como con todo lo relacionado con llevar a cabo pruebas adecuadas, es esencial identificar la tecnología que se está usando. Abusar de la capa ORM

Tras identificar el posible ORM que se esté usando, resulta esencial entender cómo funciona su analizador (parser) y estudiar métodos para abusar de él, o incluso, si la aplicación usa una versión antigua, identificar los CVE relacionados con la biblioteca utilizada. A veces, las capas ORM no están correctamente implementadas y, por tanto, permiten al evaluador realizar inyección SQL normal, sin preocuparse por la capa ORM.

Implementación débil del ORM

Un escenario vulnerable en el que la capa ORM no se implementó correctamente, tomado de SANS:

List results = session.createQuery("from Orders as orders where orders.id = " + currentOrder.getId()).list();
List results = session.createSQLQuery("Select * from Books where author = " + book.getAuthor()).list();

Lo anterior no implementó el parámetro posicional, que permite al desarrollador reemplazar la entrada por un ?. Un ejemplo sería el siguiente:

Query hqlQuery = session.createQuery("from Orders as orders where orders.id = ?");
List results = hqlQuery.setString(0, "123-ADB-567-QTWYTFDL").list(); // 0 is the first position, where it is dynamically replaced by the string set

Esta implementación deja la validación y la sanitización a cargo de la capa ORM, y la única forma de eludirla sería identificando un problema en la propia capa ORM.

Capa ORM vulnerable

Las capas ORM son código, y la mayoría de las veces son bibliotecas de terceros. Pueden ser vulnerables igual que cualquier otra pieza de código. Un ejemplo podría ser la biblioteca npm del ORM sequelize, que se descubrió vulnerable en 2019. En otra investigación realizada por RIPS Tech, se identificaron formas de eludir el ORM hibernate usado en Java.

Basándose en su artículo de blog, se puede esbozar una hoja de referencia que podría permitir al evaluador identificar problemas, como sigue:
