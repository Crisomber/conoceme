MS Access

Resumen

Como se explica en la sección genérica de inyección SQL, las vulnerabilidades de inyección SQL ocurren siempre que se utiliza una entrada proporcionada por el usuario en la construcción de una consulta SQL sin estar adecuadamente restringida o sanitizada. Esta clase de vulnerabilidades permite a un atacante ejecutar código SQL con los privilegios del usuario utilizado para conectarse a la base de datos. En esta sección se tratarán técnicas de inyección SQL relevantes que aprovechan características específicas de Microsoft Access.

Cómo probar

Identificación (fingerprinting)

Identificar la tecnología de base de datos específica al probar una aplicación basada en SQL es el primer paso para evaluar adecuadamente las posibles vulnerabilidades. Un enfoque común consiste en inyectar patrones de ataque de inyección SQL estándar (por ejemplo, comilla simple, comilla doble, etc.) para provocar excepciones de la base de datos. Suponiendo que la aplicación no maneje las excepciones con páginas personalizadas, es posible identificar el DBMS subyacente observando los mensajes de error.

Dependiendo de la tecnología web específica utilizada, las aplicaciones basadas en MS Access responderán con uno de los siguientes errores:

Fatal error: Uncaught exception 'com_exception' with message Source: Microsoft JET Database Engine

o

Microsoft JET Database Engine error '80040e14'

o

Microsoft Office Access Database Engine

En todos los casos, tenemos la confirmación de que estamos probando una aplicación que usa una base de datos MS Access.

Pruebas básicas

Desafortunadamente, MS Access no admite los operadores habituales que tradicionalmente se usan durante las pruebas de inyección SQL, entre ellos:

  • Sin caracteres de comentario
  • Sin consultas apiladas (stacked queries)
  • Sin operador LIMIT
  • Sin operadores similares a SLEEP o BENCHMARK
  • y muchos otros

Sin embargo, es posible emular estas funciones combinando varios operadores o usando técnicas alternativas. Como se mencionó, no es posible usar el truco de insertar los caracteres /*, -- o # para truncar la consulta. No obstante, por suerte podemos eludir esta limitación inyectando un carácter 'null'. Usar un byte nulo %00 dentro de una consulta SQL hace que MS Access ignore todos los caracteres restantes. Esto puede explicarse teniendo en cuenta que todas las cadenas terminan en NULL en la representación interna que usa la base de datos. Cabe mencionar que el carácter null a veces también puede causar problemas, ya que puede truncar cadenas a nivel del servidor web. En esas situaciones, sin embargo, podemos usar otro carácter: 0x16 (%16 en formato codificado para URL).

Considérese la siguiente consulta:

SELECT [username],[password] FROM users WHERE [username]='$myUsername' AND [password]='$myPassword'

Podemos truncar la consulta con las siguientes dos URL:

  • https://www.example.com/page.asp?user=admin'%00&pass=foo
  • https://www.example.com/page.app?user=admin'%16&pass=foo

El operador LIMIT no está implementado en MS Access; sin embargo, es posible limitar el número de resultados usando los operadores TOP o LAST en su lugar.

https://www.example.com/page.app?id=2'+UNION+SELECT+TOP+3+name+FROM+appsTable%00

Combinando ambos operadores, es posible seleccionar resultados específicos. La concatenación de cadenas es posible usando los caracteres & (%26) y + (%2b).

También hay muchas otras funciones que pueden usarse al probar inyección SQL, entre ellas, pero no limitadas a:

  • ASC: obtiene el valor ASCII de un carácter pasado como entrada
  • CHR: obtiene el carácter correspondiente al valor ASCII pasado como entrada
  • LEN: devuelve la longitud de la cadena pasada como parámetro
  • IIF: es la construcción IF; por ejemplo, la siguiente sentencia IIF(1=1, 'a', 'b') devuelve a
  • MID: esta función permite extraer una subcadena; por ejemplo, la siguiente sentencia mid('abc',1,1) devuelve a
  • TOP: esta función permite especificar el número máximo de resultados que debe devolver la consulta desde el principio. Por ejemplo, TOP 1 devolverá solo 1 fila.
  • LAST: esta función se usa para seleccionar solo la última fila de un conjunto de filas. Por ejemplo, la siguiente consulta SELECT last(*) FROM users devolverá solo la última fila del resultado.

Algunos de estos operadores son esenciales para explotar inyecciones SQL ciegas. Para otros operadores avanzados, consúltense los documentos en las referencias.

Enumeración de atributos

Para enumerar las columnas de una tabla de la base de datos, es posible usar una técnica común basada en errores. En resumen, podemos obtener el nombre de los atributos analizando los mensajes de error y repitiendo la consulta con diferentes selectores. Por ejemplo, suponiendo que conocemos la existencia de una columna, también podemos obtener el nombre de los atributos restantes con la siguiente consulta:

' GROUP BY Id%00

En el mensaje de error recibido, es posible observar el nombre de la siguiente columna. En este punto, podemos iterar el método hasta obtener el nombre de todos los atributos. Si no conocemos el nombre del primer atributo, aun podemos insertar un nombre de columna ficticio y obtener el nombre del primer atributo dentro del mensaje de error.

Obtención del esquema de la base de datos

En MS Access existen por defecto varias tablas de sistema que potencialmente pueden usarse para obtener los nombres de tablas y columnas. Desafortunadamente, en la configuración por defecto de las versiones recientes de la base de datos MS Access, estas tablas no son accesibles. Sin embargo, siempre vale la pena intentarlo:

  • MSysObjects
  • MSysACEs
  • MSysAccessXML

Por ejemplo, si existe una vulnerabilidad de inyección SQL de tipo union, se puede usar la siguiente consulta:

' UNION SELECT Name FROM MSysObjects WHERE Type = 1%00

Alternativamente, siempre es posible forzar por fuerza bruta el esquema de la base de datos usando una lista de palabras estándar (por ejemplo, FuzzDb).

En algunos casos, los desarrolladores o administradores de sistemas no se dan cuenta de que incluir el archivo .mdb real dentro de la raíz web de la aplicación puede permitir descargar toda la base de datos. Los nombres de archivo de la base de datos pueden inferirse con la siguiente consulta:

https://www.example.com/page.app?id=1'+UNION+SELECT+1+FROM+name.table%00

donde name es el nombre del archivo .mdb y table es una tabla válida de la base de datos. En el caso de bases de datos protegidas con contraseña, pueden usarse varias utilidades de software para descifrar la contraseña. Consúltense las referencias.

Pruebas de inyección SQL ciega

Las vulnerabilidades de Blind SQL Injection no son, en absoluto, las inyecciones SQL más fáciles de explotar al probar aplicaciones reales. En el caso de las versiones recientes de MS Access, tampoco es posible ejecutar comandos de shell ni leer o escribir archivos arbitrarios.

En el caso de las inyecciones SQL ciegas, el atacante solo puede inferir el resultado de la consulta evaluando diferencias de tiempo o las respuestas de la aplicación. Se supone que el lector ya conoce la teoría detrás de los ataques de inyección SQL ciega, ya que el resto de esta sección se centrará en los detalles específicos de MS Access.

Se usa el siguiente ejemplo:

https://www.example.com/index.php?myId=[sql]

donde el parámetro ID se usa dentro de la siguiente consulta:

SELECT * FROM orders WHERE [id]=$myId

Consideremos que el parámetro myId es vulnerable a inyección SQL ciega. Como atacantes, queremos extraer el contenido de la columna username en la tabla users, suponiendo que ya hemos descubierto el esquema de la base de datos.

Una consulta típica que puede usarse para inferir el primer carácter del username de la fila número 10 es:

https://www.example.com/index.php?id=IIF((select%20MID(LAST(username),1,1)%20from%20(select%20TOP%2010%20username%20from%20users)='a',0,'no')

Si el primer carácter es a, la consulta devolverá 0; de lo contrario, devolverá la cadena no.

Usando una combinación de las funciones IFF, MID, LAST y TOP, es posible extraer el primer carácter del username en una fila específicamente seleccionada. Como la consulta interna devuelve un conjunto de registros, y no solo uno, no es posible usarla directamente. Por suerte, podemos combinar varias funciones para extraer una cadena específica.

Supongamos que queremos recuperar el username de la fila número 10. Primero, podemos usar la función TOP para seleccionar las primeras diez filas usando la siguiente consulta:

SELECT TOP 10 username FROM users

Luego, usando este subconjunto, podemos extraer la última fila usando la función LAST. Una vez que tenemos solo una fila, y exactamente la fila que contiene nuestra cadena, podemos usar las funciones IFF, MID y LAST para inferir el valor real del username. En nuestro ejemplo, usamos IFF para devolver un número o una cadena. Usando este truco, podemos distinguir si tenemos una respuesta verdadera o no, observando las respuestas de error de la aplicación. Como id es numérico, la comparación con una cadena da como resultado un error SQL que potencialmente podría filtrarse mediante páginas 500 Internal Server Error. De lo contrario, probablemente se devolverá una página 200 OK estándar.

Por ejemplo, podemos tener la siguiente consulta:

https://www.example.com/index.php?id='%20AND%201=0%20OR%20'a'=IIF((select%20MID(LAST(username),1,1)%20from%20(select%20TOP%2010%20username%20from%20users))='a','a','b')%00

que es VERDADERA si el primer carácter es 'a', o falsa en caso contrario.

Como se mencionó, este método permite inferir el valor de cadenas arbitrarias dentro de la base de datos:

  1. Probando todos los valores imprimibles, hasta encontrar una coincidencia
  2. Infiriendo la longitud de la cadena usando la función LEN, o simplemente deteniéndose cuando ya se han encontrado todos los caracteres

Las inyecciones SQL ciegas basadas en tiempo también son posibles abusando de consultas pesadas.
