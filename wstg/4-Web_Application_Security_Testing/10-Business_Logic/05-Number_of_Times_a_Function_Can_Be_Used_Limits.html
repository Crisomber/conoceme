Límites en el número de veces que se puede usar una función

ID
WSTG-BUSL-05

Resumen

Muchos de los problemas que resuelven las aplicaciones requieren límites en el número de veces que se puede usar una función o ejecutar una acción. Las aplicaciones deben ser "lo bastante inteligentes" para no permitir que el usuario exceda su límite de uso de estas funciones, ya que en muchos casos cada vez que se usa la función el usuario puede obtener algún tipo de beneficio que debe contabilizarse para compensar adecuadamente al propietario. Por ejemplo: un sitio de comercio electrónico puede permitir a los usuarios aplicar un descuento solo una vez por transacción, o algunas aplicaciones pueden estar en un plan de suscripción y permitir a los usuarios descargar solo tres documentos completos al mes.

Las vulnerabilidades relacionadas con la prueba de los límites de las funciones son específicas de cada aplicación y se deben crear casos de uso indebido que busquen ejercitar partes de la aplicación, funciones o acciones más veces de las permitidas.

Los atacantes pueden ser capaces de eludir la lógica de negocio y ejecutar una función más veces de lo "permitido", explotando la aplicación para su beneficio personal.

Ejemplo

Supóngase que un sitio de comercio electrónico permite a los usuarios aprovechar uno de entre muchos descuentos sobre su compra total y luego proceder a la caja y al pago. ¿Qué pasa si el atacante vuelve a la página de descuentos después de haber tomado y aplicado el único descuento "permitido"? ¿Puede aprovechar otro descuento? ¿Puede aprovechar el mismo descuento varias veces?

Objetivos de la prueba

  • Identificar las funciones que deben establecer límites al número de veces que pueden ser llamadas.
  • Evaluar si hay un límite lógico establecido en las funciones y si se valida correctamente.

Cómo probar

  • Revisar la documentación del proyecto y usar pruebas exploratorias buscando funciones o características de la aplicación o del sistema que no deberían ejecutarse más de una sola vez o un número especificado de veces durante el flujo de trabajo de la lógica de negocio.
  • Para cada una de las funciones y características encontradas que solo deberían ejecutarse una vez o un número especificado de veces durante el flujo de trabajo de la lógica de negocio, desarrollar casos de abuso o uso indebido que puedan permitir a un usuario ejecutarlas más veces de las permitidas. Por ejemplo, ¿puede un usuario navegar hacia adelante y hacia atrás por las páginas varias veces ejecutando una función que solo debería ejecutarse una vez?, o ¿puede un usuario cargar y descargar carritos de compra permitiendo descuentos adicionales?

Casos de prueba relacionados

  • Account Enumeration and Guessable User Account
  • Weak lock out mechanism

Corrección

La aplicación debe establecer controles estrictos para evitar el abuso de los límites. Esto puede lograrse haciendo que un cupón deje de ser válido a nivel de base de datos, o estableciendo un contador límite por usuario a nivel de backend o de base de datos, ya que todos los usuarios deben estar identificados mediante una sesión; se elegirá lo que sea mejor para el requisito de negocio.
