Credenciales predeterminadas

ID
WSTG-ATHN-02

Resumen

Muchas aplicaciones web y dispositivos de hardware tienen contraseñas predeterminadas para la cuenta administrativa integrada. Aunque en algunos casos estas pueden generarse de forma aleatoria, a menudo son estáticas, lo que significa que un atacante puede adivinarlas u obtenerlas con facilidad.

Además, cuando se crean nuevos usuarios en las aplicaciones, es posible que estos tengan contraseñas predefinidas. Estas podrían ser generadas automáticamente por la aplicación o creadas manualmente por el personal. En ambos casos, si no se generan de forma segura, un atacante podría adivinar las contraseñas.

Objetivos de la prueba

  • Determinar si la aplicación tiene cuentas de usuario con contraseñas predeterminadas.
  • Revisar si las nuevas cuentas de usuario se crean con contraseñas débiles o predecibles.

Cómo probar

Credenciales predeterminadas del fabricante

El primer paso para identificar contraseñas predeterminadas es identificar el software que se utiliza. Esto se trata en detalle en la sección Recopilación de información de la guía.

Una vez identificado el software, se debe intentar averiguar si utiliza contraseñas predeterminadas y, de ser así, cuáles son. Esto debe incluir:

  • Buscar "[SOFTWARE] default password".
  • Revisar el manual o la documentación del fabricante.
  • Consultar bases de datos de contraseñas predeterminadas comunes, como CIRT.net, SecLists Default Passwords o DefaultCreds-cheat-sheet.
  • Inspeccionar el código fuente de la aplicación (si está disponible).
  • Instalar la aplicación en una máquina virtual e inspeccionarla.
  • Inspeccionar el hardware físico en busca de etiquetas adhesivas (frecuentes en dispositivos de red).

Si no se encuentra una contraseña predeterminada, se deben probar opciones comunes como:

  • "admin", "password", "12345" u otras contraseñas predeterminadas comunes.
  • Una contraseña vacía o en blanco.
  • El número de serie o la dirección MAC del dispositivo.

Si se desconoce el nombre de usuario, existen varias opciones para enumerar usuarios, tratadas en la guía de Enumeración de cuentas. Alternativamente, se pueden probar opciones comunes como "admin", "root" o "system".

Contraseñas predeterminadas de la organización

Cuando el personal de una organización crea manualmente contraseñas para cuentas nuevas, es posible que lo haga de forma predecible. Con frecuencia pueden ser:

  • Una única contraseña común como "Password1".
  • Detalles específicos de la organización, como su nombre o dirección.
  • Contraseñas que siguen un patrón sencillo, como "Monday123" si la cuenta se crea un lunes.

Este tipo de contraseñas suele ser difícil de identificar desde una perspectiva de caja negra, a menos que se logren adivinar o descubrir por fuerza bruta. Sin embargo, son fáciles de identificar al realizar pruebas de caja gris o de caja blanca.

Contraseñas predeterminadas generadas por la aplicación

Si la aplicación genera automáticamente contraseñas para las nuevas cuentas de usuario, estas también pueden ser predecibles. Para probarlo, se deben crear varias cuentas en la aplicación con datos similares al mismo tiempo y comparar las contraseñas que se les asignan.

Las contraseñas pueden basarse en:

  • Una única cadena estática compartida entre cuentas.
  • Una parte con hash u ofuscada de los datos de la cuenta, como md5($username).
  • Un algoritmo basado en el tiempo.
  • Un generador de números pseudoaleatorios (PRNG) débil.

Este tipo de problema suele ser difícil de identificar desde una perspectiva de caja negra.
