Introducción a la recopilación de información

Solo se puede probar lo que se logra encontrar. Antes de evaluar la autenticación, la autorización, la lógica de negocio o cualquier otra área de una aplicación, el evaluador debe identificar primero qué está realmente dentro del alcance: las aplicaciones, los hosts, los endpoints y las tecnologías que conforman la superficie de ataque. Los activos que nunca se descubren nunca se prueban, sin importar qué tan exhaustivo sea el resto de la evaluación.

Por lo tanto, la recopilación de información y el descubrimiento son la base de cualquier evaluación de seguridad de aplicaciones web. Combinan el reconocimiento pasivo (que no interactúa directamente con el objetivo) con la enumeración activa (que sí lo hace) para construir una imagen lo más completa posible de lo que está expuesto, de cómo está expuesto y de qué tecnologías intervienen.

Las evaluaciones actuales suelen combinar la enumeración pasiva de subdominios (subfinder, Amass en modo pasivo), el sondeo de hosts activos (httpx), Certificate Transparency, la recopilación de URL de archivos históricos (gau, waybackurls, waymore), el análisis de JavaScript (jsluice, LinkFinder) y el descubrimiento de contenido dirigido (ffuf, feroxbuster, Kiterunner). Consulta los escenarios INFO individuales y el capítulo API Reconnaissance para ver ejemplos concretos.

Mantente siempre dentro del alcance definido del trabajo.
