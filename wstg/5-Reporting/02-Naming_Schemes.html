Esquemas de nomenclatura de vulnerabilidades

Con un número cada vez mayor de activos de TI que administrar, los profesionales de la seguridad requieren herramientas nuevas y más potentes para realizar análisis automatizados y a gran escala. Gracias al software, la atención puede centrarse en los problemas más creativos e intelectualmente desafiantes. Lamentablemente, lograr que las herramientas de evaluación de vulnerabilidades, el software antivirus y los sistemas de detección de intrusiones se comuniquen entre sí no es una tarea fácil. Esto ha dado lugar a varias complicaciones técnicas y ha exigido una forma estandarizada de identificar cada fallo de software, vulnerabilidad o problema de configuración identificado. La falta de esta capacidad de interoperabilidad puede causar inconsistencias durante la evaluación de seguridad, informes confusos y esfuerzos adicionales de correlación, entre otros problemas que producirán un importante desperdicio de recursos y de tiempo.

Un esquema de nomenclatura es una metodología sistemática utilizada para identificar cada una de esas vulnerabilidades con el fin de facilitar su identificación clara y el intercambio de información. Este objetivo se logra mediante la definición de un nombre único, estructurado y eficiente para el software para cada vulnerabilidad. Existen múltiples esquemas utilizados para facilitar este esfuerzo; los más comunes son:

  • Common Platform Enumeration (CPE)
  • Software Identification Tag (SWID)
  • Package URL (PURL)

Software Identification Tag

Software Identification Tag (SWID) es un estándar de la International Organization for Standardization definido por la norma ISO/IEC 19770-2:2015. Las etiquetas SWID se utilizan para identificar claramente cada software como parte de ciclos de vida integrales de gestión de activos de software. El National Institute of Standards and Technology (NIST) recomienda este esquema de información como la identificación principal de cualquier software desarrollado o instalado. A partir de SWID es posible generar otros esquemas, como el CPE utilizado por la National Vulnerability Database (NVD), mientras que el proceso inverso no es posible.

Cada etiqueta SWID se representa en un formato XML estandarizado. Una etiqueta SWID se compone de tres grupos de elementos. El primer bloque está compuesto por 7 elementos predefinidos necesarios para considerarla una etiqueta válida. Le sigue un bloque opcional que proporciona un conjunto de 30 posibles elementos predefinidos que el creador de la etiqueta puede utilizar para aportar información fiable y detallada. Por último, el grupo Extended de elementos brinda al creador de la etiqueta la oportunidad de definir cualquier elemento no predefinido que se requiera para definir con precisión el software descrito. El alto nivel de granularidad que ofrece SWID no solo permite describir un producto de software determinado, sino también su estado específico en el ciclo de vida del software.

Ejemplos

  • El parche ACME Roadrunner Service Pack 1 creado por la ACME Corporation para el producto ya instalado identificado con el @tagId: com.acme.rms-ce-v4-1-5-0:
<SoftwareIdentity
                  xmlns="https://standards.iso.org/iso/19770/-2/2015/schema.xsd"
                  name="ACME Roadrunner Service Pack 1"
                  tagId="com.acme.rms-ce-sp1-v1-0-0"
                  patch="true"
                  version="1.0.0">
  <Entity
          name="The ACME Corporation"
          regid="acme.com"
          role="tagCreator softwareCreator"/>
  <Link
        rel="patches"
        href="swid:com.acme.rms-ce-v4-1-5-0">
    ...
</SoftwareIdentity>
  • Red Hat Enterprise Linux versión 8 para la arquitectura x86-64:
<SoftwareIdentity
                  xmlns="https://standards.iso.org/iso/19770/-2/2015/schema.xsd"
                  xmlns:xsi="https://www.w3.org/2001/XMLSchema-instance"
                  xsi:schemaLocation="https://standards.iso.org/iso/19770/-2/2015/schema.xsd"
                  xml:lang="en-US"
                  name="Red Hat Enterprise Linux"
                  tagId="com.redhat.RHEL-8-x86_64"
                  tagVersion="1"
                  version="8"
                  versionScheme="multipartnumeric"
                  media="(OS:linux)">

Common Platform Enumeration

El esquema Common Platform Enumeration (CPE) es un esquema de nomenclatura estructurado para sistemas de tecnologías de la información, software y paquetes mantenido por la NVD. Se utiliza comúnmente junto con los códigos de identificación de Common Vulnerabilities and Exposures (p. ej., CVE-2017-0147). A pesar de considerarse un esquema obsoleto reemplazado por SWID, CPE sigue siendo ampliamente utilizado por varias soluciones de seguridad.

Se define como un diccionario de valores registrados proporcionado por la NVD. Cada código CPE puede definirse como un nombre bien formateado o como una URL. Cada valor DEBE seguir esta estructura:

  • cpe-name = "cpe:" component-list
  • component-list = part ":" vendor ":" product ":" version ":" update ":" edition ":" lang
  • component-list = part ":" vendor ":" product ":" version ":" update ":" edition
  • component-list = part ":" vendor ":" product ":" version ":" update
  • component-list = part ":" vendor ":" product ":" version
  • component-list = part ":" vendor ":" product
  • component-list = part ":" vendor
  • component-list = part
  • component-list = empty
  • part = "h" / "o" / "a" = string
  • vendor = string
  • product = string
  • version = string
  • update = string
  • edition = string
  • lang LANGTAG / empty
  • string = *( unreserved / pct-encoded )
  • empty = ""
  • unreserved = ALPHA / DIGIT / "-" / "." / "_" / " ̃"
  • pct-encoded = "%" HEXDIG HEXDIG
  • ALPHA = %x41-5a / %x61-7a ; A-Z or a-z
  • DIGIT = %x30-39 ; 0-9
  • HEXDIG = DIGIT / "a" / "b" / "c" / "d" / "e" / "f"
  • LANGTAG = cf. [RFC5646]

Ejemplos

  • Microsoft Internet Explorer 8.0.6001 Beta (cualquier edición): wfn:[part="a",vendor="microsoft",product="internet_explorer", version="8\.0\.6001",update="beta",edition=ANY] que se enlaza con la siguiente URL: cpe:/a:microsoft:internet_explorer:8.0.6001:beta.
  • Foo\Bar Big$Money Manager 2010 Special Edition para iPod Touch 80GB: wfn:[part="a",vendor="foo\\bar",product="big\$money_manager_2010", sw_edition="special",target_sw="ipod_touch",target_hw="80gb"], que se enlaza con la siguiente URL: cpe:/a:foo%5cbar:big%24money_manager_2010:::~~special~ipod_touch~80gb~.

Package URL

Package URL estandariza la forma en que se representan los metadatos de los paquetes de software para que los paquetes puedan localizarse universalmente, sin importar a qué proveedor, proyecto o ecosistema pertenezcan.

Una PURL es una URL definida como una cadena ASCII válida según RFC3986, compuesta por siete elementos. Cada uno de ellos está separado por un carácter definido para que el software pueda manipularla fácilmente.

scheme:type/namespace/name@version?qualifiers#subpath

La definición de cada componente es:

  • scheme: valor constante conforme al esquema de URL, "pkg". (Obligatorio).
  • type: tipo de paquete o protocolo del paquete, como maven, npm, nuget, gem, pypi, etc. (Obligatorio).
  • namespace: valor específico del tipo que actúa como prefijo del paquete, como el nombre de su propietario, el groupid, etc. (Opcional).
  • name: nombre del paquete. (Obligatorio).
  • version: versión del paquete. (Opcional).
  • qualifiers: datos calificadores adicionales de un paquete, como un sistema operativo, una arquitectura, una distribución, etc. (Opcional).
  • subpath: subruta adicional dentro de un paquete, relativa a la raíz del paquete. (Opcional).

Ejemplos

  • El software Curl, empaquetado como un paquete .deb para Debian Jessie destinado a una arquitectura i386: pkg:deb/debian/curl@7.50.3-1?arch=i386&distro=jessie
  • Imagen Docker de Apache Casandra firmada con el hash SHA256 244fd47e07d1004f0aed9c: pkg:docker/cassandra@sha256:244fd47e07d1004f0aed9c

Usos recomendados

USO RECOMENDACIÓN
Aplicación cliente o servidor CPE o SWID
Contenedor PURL o SWID
Firmware CPE o SWID*
Biblioteca o framework (paquete) PURL
Biblioteca o framework (no paquete) SWID
Sistema operativo CPE o SWID
Paquete de sistema operativo PURL o SWID

Nota: Debido al estado obsoleto de CPE, la recomendación de la industria parece ser que los nuevos proyectos implementen SWID cuando necesiten decidir entre los dos métodos. Aun así, se sabe que CPE es un esquema de nomenclatura ampliamente utilizado en los proyectos y soluciones activos actuales.
