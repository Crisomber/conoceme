¿Por qué OWASP?

El Open Worldwide Application Security Project® (OWASP®) es una fundación sin fines de lucro cuya visión es que no exista más software inseguro. Su misión es ser la comunidad abierta global que impulsa el software seguro mediante la educación, las herramientas y la colaboración.

Crear una guía como esta requiere la experiencia de cientos de personas en todo el mundo. Hay muchas maneras de probar fallos de seguridad, y esta guía intenta recoger el consenso sobre cómo realizar esas pruebas de forma rápida, precisa y eficiente. OWASP reúne a profesionales para formar un enfoque de mejores prácticas ante los problemas de seguridad del software, como una comunidad neutral respecto a los proveedores y no como un vendedor comercial ni un regulador.

Hacer que esta guía sea completamente gratuita y abierta respalda esa misión. Cualquiera puede aprender las técnicas utilizadas para probar los problemas de seguridad más comunes. La seguridad no debería ser un arte oscuro ni un secreto cerrado. Debe estar abierta a los profesionales de la seguridad, pero también a desarrolladores, QA y gerentes técnicos. Este proyecto mantiene esa experiencia en manos de las personas que construyen y entregan software.

Esta guía debe llegar a los desarrolladores y a los evaluadores de software. No existen ni de lejos suficientes especialistas en seguridad de aplicaciones para resolver el problema por sí solos. Gran parte de la responsabilidad de la seguridad de las aplicaciones recae en los desarrolladores, porque son quienes escriben el código. No se puede esperar que los desarrolladores produzcan software seguro si nunca prueban las clases de errores que introducen vulnerabilidades.

Mantener esta información actualizada es fundamental. La comunidad de OWASP mantiene y amplía esta guía mediante Issues y Pull Requests en GitHub para que pueda mantenerse al ritmo del panorama de amenazas a la seguridad de las aplicaciones.

Esta guía es un testimonio de la pasión y la energía de los miembros de OWASP y de los voluntarios del proyecto. Ayuda a cambiar el mundo una línea de código a la vez.

Adaptación y priorización

Adopta esta guía en tu organización. Adapta el material a tus tecnologías, procesos y estructura.

Varios roles utilizan esta guía con frecuencia:

  • Los desarrolladores deben usar esta guía para ayudar a producir código seguro. Estas pruebas deben formar parte de los procedimientos normales de código y de pruebas unitarias.
  • Los evaluadores de software y QA deben usar esta guía para ampliar los casos de prueba que aplican. Detectar estas vulnerabilidades de forma temprana ahorra una cantidad considerable de tiempo, esfuerzo y dinero más adelante.
  • Los especialistas en seguridad deben usar esta guía junto con otras técnicas para verificar que no se hayan pasado por alto problemas de seguridad.
  • Los gerentes de proyecto deben tratar los problemas de seguridad como errores en el código y en el diseño, y planificar en consecuencia.

Al realizar pruebas de seguridad, hay que repriorizar continuamente. Hay infinitas maneras en que una aplicación podría fallar, y las organizaciones siempre tienen tiempo y recursos de prueba limitados. Dedica ese tiempo a los problemas de seguridad que presentan un riesgo real para el negocio. Contextualiza el riesgo en términos de la aplicación y sus casos de uso.

Considera esta guía como un conjunto de técnicas para encontrar distintos tipos de problemas de seguridad. No todas las técnicas son igualmente importantes para cada sistema. Evita tratar la guía como una lista de verificación. Siguen apareciendo nuevas vulnerabilidades y ninguna guía puede ser una lista exhaustiva de lo que se debe probar. Úsala como un buen punto de partida.

El papel de las herramientas automatizadas

Las herramientas de seguridad automatizadas, como las de pruebas dinámicas de seguridad de aplicaciones (DAST), pruebas estáticas de seguridad de aplicaciones (SAST) y análisis de composición de software (SCA), ayudan a escalar las pruebas y a encontrar muchas clases de problemas. Se deben usar para lo que hacen bien: amplitud de cobertura, comprobaciones repetibles y aplicación de políticas básicas. Las herramientas abiertas del ecosistema, incluida ZAP, pueden apoyar ese trabajo sin atar a los equipos a un único proveedor.

Aun así, estas herramientas son genéricas. Están creadas para aplicaciones en general, no para tu código personalizado ni tus reglas de negocio. Pueden encontrar muchos problemas comunes, pero con frecuencia carecen del contexto específico de la aplicación necesario para detectar fallos más profundos. Los problemas más graves suelen estar entrelazados con la lógica de negocio y el diseño personalizado, que es donde las técnicas de esta guía resultan más valiosas.

Ejecutar una herramienta suele ser rápido. Investigar y verificar cada hallazgo lleva tiempo. Si el objetivo es encontrar y eliminar los fallos más graves lo más rápido posible, hay que equilibrar el escaneo automatizado con las técnicas manuales y semiautomatizadas descritas aquí. Los programas de seguridad de aplicaciones bien equilibrados usan ambos: herramientas para la amplitud, y esta guía para la profundidad y el criterio.

Llamado a la acción

Si construyes, diseñas o pruebas software, familiarízate con la guía de pruebas de seguridad de este documento. Es una hoja de ruta para probar muchos de los problemas que enfrentan las aplicaciones hoy en día, pero no es exhaustiva. Si encuentras errores o vacíos, abre un Issue o envía un Pull Request en el repositorio de GitHub del WSTG. Eso ayuda a miles de personas más que usan esta guía.

Por favor, considera unirte a nosotros como miembro individual o corporativo para que podamos seguir produciendo materiales como esta guía de pruebas y los demás proyectos de OWASP.

Gracias a todos los colaboradores pasados y futuros de esta guía. Su trabajo ayuda a que las aplicaciones de todo el mundo sean más seguras.
