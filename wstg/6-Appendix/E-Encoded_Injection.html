E. Inyección codificada

Antecedentes

La codificación de caracteres es el proceso de asignar caracteres, números y otros símbolos a un formato estándar. Normalmente esto se hace para crear un mensaje listo para su transmisión entre el emisor y el receptor. Es, en términos simples, la conversión de caracteres (pertenecientes a distintos idiomas como el inglés, el chino, el griego o cualquier otro idioma conocido) en bytes. Un ejemplo de un esquema de codificación de caracteres ampliamente utilizado es el American Standard Code for Information Interchange (ASCII), que inicialmente usaba códigos de 7 bits. Ejemplos más recientes de esquemas de codificación son los estándares de la industria informática Unicode UTF-8 y UTF-16.

En el ámbito de la seguridad de aplicaciones, y debido a la abundancia de esquemas de codificación disponibles, la codificación de caracteres tiene un uso indebido muy popular. Se utiliza para codificar cadenas de inyección maliciosas de manera que queden ofuscadas. Esto puede llevar a la elusión de los filtros de validación de entrada, o aprovechar formas particulares en que los navegadores representan el texto codificado.

Codificación de entrada: evasión de filtros

Las aplicaciones web suelen emplear distintos tipos de mecanismos de filtrado de entrada para limitar lo que el usuario puede enviar. Si estos filtros de entrada no se implementan lo suficientemente bien, es posible hacer pasar uno o dos caracteres a través de ellos. Por ejemplo, un / puede representarse como 2F (hexadecimal) en ASCII, mientras que el mismo carácter (/) se codifica como C0 AF en Unicode (secuencia de 2 bytes). Por lo tanto, es importante que el control de filtrado de entrada conozca el esquema de codificación utilizado. Si se descubre que el filtro solo detecta inyecciones codificadas en UTF-8, se puede emplear un esquema de codificación diferente para eludirlo.

Codificación de salida: consenso entre servidor y navegador

Los navegadores web necesitan conocer el esquema de codificación utilizado para mostrar una página web de manera coherente. Idealmente, esta información debe proporcionarse al navegador en el campo de la cabecera HTTP (Content-Type), como se muestra a continuación:

Content-Type: text/html; charset=UTF-8

o mediante la etiqueta META de HTML (META HTTP-EQUIV), como se muestra a continuación:

<META http-equiv="Content-Type" content="text/html; charset=ISO-8859-1">

Es a través de estas declaraciones de codificación de caracteres como el navegador entiende qué conjunto de caracteres utilizar al convertir bytes en caracteres. Ten en cuenta que el tipo de contenido mencionado en la cabecera HTTP tiene precedencia sobre la declaración de la etiqueta META.

CERT lo describe aquí de la siguiente manera:

Muchas páginas web dejan sin definir la codificación de caracteres (el parámetro charset en HTTP). En versiones anteriores de HTML y HTTP, se suponía que la codificación de caracteres era por defecto ISO-8859-1 si no se definía. En realidad, muchos navegadores tenían un valor por defecto diferente, por lo que no era posible confiar en que el valor por defecto fuera ISO-8859-1. La versión 4 de HTML legitima esto: si no se especifica la codificación de caracteres, se puede usar cualquier codificación de caracteres.

Si el servidor web no especifica qué codificación de caracteres está en uso, no puede saber qué caracteres son especiales. Las páginas web sin codificación de caracteres especificada funcionan la mayoría de las veces porque la mayoría de los conjuntos de caracteres asignan los mismos caracteres a los valores de byte por debajo de 128. Pero, ¿cuáles de los valores por encima de 128 son especiales? Algunos esquemas de character-encoding de 16 bits tienen representaciones multibyte adicionales para caracteres especiales como <. Algunos navegadores reconocen esta codificación alternativa y actúan en consecuencia. Este es un comportamiento "correcto", pero hace que los ataques mediante scripts maliciosos sean mucho más difíciles de prevenir. El servidor simplemente no sabe qué secuencias de bytes representan los caracteres especiales.

Por lo tanto, en caso de no recibir del servidor la información sobre la codificación de caracteres, el navegador intenta adivinar el esquema de codificación o recurre a un esquema por defecto. En algunos casos, el usuario establece explícitamente la codificación por defecto en el navegador con un esquema diferente. Cualquier discrepancia de este tipo en el esquema de codificación utilizado por la página web (servidor) y el navegador puede hacer que el navegador interprete la página de una manera no prevista o inesperada.

Inyecciones codificadas

Todos los escenarios que se presentan a continuación forman solo un subconjunto de las diversas maneras en que se puede lograr la ofuscación para eludir los filtros de entrada. Además, el éxito de las inyecciones codificadas depende del navegador utilizado. Por ejemplo, las inyecciones codificadas en US-ASCII antes tenían éxito solo en el navegador IE, pero no en Firefox. Por lo tanto, cabe señalar que las inyecciones codificadas, en gran medida, dependen del navegador.

Codificación básica

Considera un filtro básico de validación de entrada que protege contra la inyección del carácter de comilla simple. En este caso, la siguiente inyección eludiría fácilmente este filtro:

<script>alert(String.fromCharCode(88,83,83))</script>

La función de JavaScript String.fromCharCode toma los valores Unicode dados y devuelve la cadena correspondiente. Esta es una de las formas más básicas de inyecciones codificadas. Otro vector que se puede utilizar para eludir este filtro es:

<IMG src="" onerror=javascript:alert(&quot;XSS&quot;)>

O utilizando los respectivos códigos de caracteres HTML:

<IMG src="" onerror="javascript:alert(&#34;XSS&#34;)">

Lo anterior utiliza entidades HTML para construir la cadena de inyección. La codificación de entidades HTML se utiliza para mostrar caracteres que tienen un significado especial en HTML. Por ejemplo, > funciona como un corchete de cierre de una etiqueta HTML. Para mostrar realmente este carácter en la página web, se deben insertar entidades de caracteres HTML en el código fuente de la página. Las inyecciones mencionadas anteriormente son una forma de codificación. Existen numerosas otras maneras en que se puede codificar (ofuscar) una cadena para eludir el filtro anterior.

Codificación hexadecimal

Hex, abreviatura de hexadecimal, es un sistema de numeración en base 16, es decir, tiene 16 valores diferentes, del 0 al 9 y de la A a la F, para representar diversos caracteres. La codificación hexadecimal es otra forma de ofuscación que a veces se utiliza para eludir los filtros de validación de entrada. Por ejemplo, la versión codificada en hexadecimal de la cadena <IMG SRC=javascript:alert('XSS')> es

<IMG SRC=%6A%61%76%61%73%63%72%69%70%74%3A%61%6C%65%72%74%28%27%58%53%53%27%29>

A continuación se muestra una variación de la cadena anterior. Se puede usar en caso de que se esté filtrando el carácter ‘%’:

<IMG SRC=&#x6A&#x61&#x76&#x61&#x73&#x63&#x72&#x69&#x70&#x74&#x3A&#x61&#x6C&#x65&#x72&#x74&#x28&#x27&#x58&#x53&#x53&#x27&#x29>

Existen otros esquemas de codificación, como Base64 y octal, que pueden utilizarse para la ofuscación. Aunque no todos los esquemas de codificación funcionan siempre, un poco de prueba y error, junto con manipulaciones inteligentes, sin duda revelará la brecha en un filtro de validación de entrada débilmente construido.

Codificación UTF-7

La codificación UTF-7 de

<SCRIPT>
    alert(‘XSS’);
</SCRIPT>

es la siguiente

+ADw-SCRIPT+AD4-alert('XSS');+ADw-/SCRIPT+AD4-

Para que el script anterior funcione, el navegador tiene que interpretar la página web como codificada en UTF-7.

Codificación multibyte

La codificación de ancho variable es otro tipo de esquema de codificación de caracteres que utiliza códigos de longitud variable para codificar caracteres. La codificación multibyte es un tipo de codificación de ancho variable que utiliza un número variable de bytes para representar un carácter. La codificación multibyte se utiliza principalmente para codificar caracteres que pertenecen a un conjunto de caracteres grande, p. ej., chino, japonés y coreano.

La codificación multibyte se ha utilizado en el pasado para eludir las funciones estándar de validación de entrada y llevar a cabo ataques de cross site scripting e inyección SQL.
