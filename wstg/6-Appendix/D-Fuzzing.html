D. Fuzzing

Introducción

El fuzzing es el proceso o la técnica de enviar una cantidad de peticiones a un sitio objetivo en un cierto intervalo de tiempo. En otras palabras, es también similar a la fuerza bruta. El fuzzing es un proceso que se puede llevar a cabo con herramientas como Wfuzz, ffuf, entre otras. Como evaluador, tendrías que proporcionar a la herramienta la URL objetivo, el parámetro, el endpoint, etc., y algún tipo de entradas. Luego la herramienta de fuzzing construye las peticiones y las envía al objetivo. Una vez finalizado el fuzzing, es necesario analizar las respuestas, los tiempos, los códigos de estado y otras características en busca de posibles vulnerabilidades.

¿Por qué usar fuzzing?

Probar vulnerabilidades introduciendo las entradas una por una de forma manual puede ser caótico. En la era actual, en la que las personas tienen menos tiempo y bajos niveles de paciencia, la idea de introducir manualmente entradas para encontrar errores o vulnerabilidades puede resultar abrumadora. Para reducir esta percepción y ahorrar tiempo, el fuzzing puede ser un gran punto a favor. El fuzzing es un proceso automatizado en el que gran parte del trabajo duro lo realiza una herramienta de fuzzing. Todo lo que un analista tiene que hacer es analizar las diversas características una vez terminado el proceso. Considera un sitio con muchos campos de entrada para probar XSS. En un enfoque manual, todo lo que hacemos es alimentar el campo de entrada con payloads de XSS uno por uno, lo que sería demasiado agitado. En contraste, en un enfoque automatizado, todo lo que se necesita es proporcionar al fuzzer la lista de payloads de XSS y el fuzzer se encarga de todas las peticiones.

Herramientas para usar en fuzzing

Existen cientos de herramientas disponibles en la industria para hacer fuzzing. Pero a continuación se enumeran algunas de las herramientas de fuzzing más populares y mejor valoradas.

Wfuzz

Wfuzz funciona reemplazando el valor de la lista de palabras en el lugar donde se encuentra el marcador FUZZ. Para entender esto con mayor claridad, consideremos un ejemplo:

wfuzz -w userIDs.txt https://example.com/view_photo?userId=FUZZ

En el comando anterior, userIds.txt es un archivo de lista de palabras que contiene valores de ID numéricos. Aquí le estamos diciendo a wfuzz que aplique fuzzing a la petición hacia la URL de ejemplo. Esa palabra FUZZ en la URL actuará como un marcador de posición que wfuzz reemplazará con los valores de la lista de palabras. Todos los valores de ID numéricos del archivo userIDs.txt se insertarán reemplazando la palabra clave FUZZ.

Ffuf

Ffuf es una herramienta de fuzzing web escrita en el lenguaje Go, muy rápida y recursiva por naturaleza. Funciona de forma similar a Wfuzz pero, a diferencia de este, es recursiva. Ffuf también funciona reemplazando el marcador de posición FUZZ con valores de la lista de palabras. Por ejemplo:

ffuf -w userIDs.txt -u https://example.com/view_photo?userId=FUZZ

Aquí -w es la opción para la lista de palabras y -u es la opción para la URL objetivo. El resto del mecanismo de funcionamiento es el mismo que el de Wfuzz. Reemplaza el marcador FUZZ con los valores de userIDs.txt.

GoBuster

GoBuster es otro fuzzer escrito en el lenguaje Go que se utiliza sobre todo para hacer fuzzing de URI, directorios/rutas, subdominios DNS, buckets de AWS S3 y nombres de vhost, y admite concurrencia. Por ejemplo:

gobuster dir -w endpoints.txt -u https://example.com

En el comando anterior, dir especifica que estamos aplicando fuzzing a un directorio, -u es la opción para la URL y -w es la opción para la lista de palabras, donde endpoints.txt es el archivo de lista de palabras del que se tomarán los payloads. El comando ejecuta peticiones concurrentes al endpoint para encontrar los directorios disponibles.

ZAP

ZAP es un escáner de seguridad de aplicaciones web que se puede utilizar para encontrar vulnerabilidades y debilidades en aplicaciones web. También incluye un Fuzzer.

Una de las características clave de ZAP es su capacidad para realizar escaneos tanto pasivos como activos. Los escaneos pasivos consisten en observar el tráfico entre el usuario y la aplicación web, mientras que los escaneos activos consisten en enviar payloads de prueba a la aplicación web para identificar vulnerabilidades.
